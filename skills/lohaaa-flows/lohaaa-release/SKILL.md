# 发布准备与人工交接

## 目标

根据本次实际变更识别代码之外的发布条件，形成可由授权人员执行的发布、验证和回滚方案。AI 的职责止于分析、准备和记录人工反馈，不得进入生产环境执行操作或验证。

## 阶段接口

- **输入**：已经通过 `lohaaa-check` 模块统一验收的需求文件和实际变更。
- **前置门禁**：模块未完成、迁移风险未知或回滚路径不清楚时，不得向人工发布阶段移交。
- **输出**：供授权人员审阅和执行的发布前置条件、顺序、发布后操作、人工生产验证清单及回滚方案。
- **AI 完成状态**：发布材料完整并完成移交后，本技能标记为“待人工发布”；AI 不得自行标记“已发布”。
- **状态更新**：进入本技能时将需求文件的当前阶段设为“发布准备与人工交接”；人工结果记录在需求文件的发布准备和发布结果部分。

## 权限边界

AI **不得**：

- 登录、连接或操作生产环境。
- 执行部署、发布、数据库迁移、历史数据回填或回滚。
- 修改生产配置、密钥、证书、权限、功能开关、网络或基础设施。
- 启停生产任务、Worker、消费者、队列、缓存、索引或第三方集成。
- 发起生产页面、API、交易、写入或流量冒烟。
- 直接读取并据此验证生产日志、指标、数据库或用户数据。
- 代替授权人员确认生产结果，或自行把需求标记为“已发布”。

AI **可以**：

- 根据代码和非生产环境结果分析发布影响。
- 编制供授权人员审阅的命令、迁移步骤、检查清单和回滚方案，但不得在生产执行。
- 在用户明确授权的非生产环境验证发布脚本和步骤。
- 记录用户或授权操作人员明确提供的生产执行结果，并标注信息来源。

任何生产操作或生产验证都必须由用户或其授权操作人员执行。需要等待人工结果时，将状态设为“待人工执行”或“待人工确认”，不得绕过该门禁。

## 一、建立变更清单

逐项判断是否涉及：

```text
应用代码
数据库结构
历史数据
配置和环境变量
密钥、证书和权限
依赖及运行时版本
基础设施和网络
定时任务和后台 Worker
消息队列、主题和消费者
缓存、搜索索引和静态资源
第三方服务和回调
API 及客户端兼容性
日志、指标和告警
```

不涉及的项目明确标记为“不适用”，不要生成无意义步骤。

## 二、数据库结构和数据迁移

检查表、字段、类型、默认值、非空、唯一、外键、索引、视图、函数、触发器、扩展和权限变化。

每项迁移必须明确：

```text
执行时机：
执行者：
预计耗时：
数据量和锁表风险：
对旧版本代码的影响：
失败处理：
是否可逆：
完成验证：
```

历史数据迁移还要确认分批、幂等、暂停恢复、进度监控和完整性验证。

需要滚动或不停机发布时优先采用：

```text
添加兼容的新结构
→ 发布兼容新旧结构的代码
→ 分批迁移历史数据
→ 切换读写
→ 验证稳定
→ 后续发布删除旧结构
```

不得在同一次发布中删除旧结构并使应用回滚失效，除非明确采用停机方案并接受风险。

## 三、配置、密钥和权限

确认新增或修改的：

- 环境变量和配置文件
- 功能开关
- 数据库或外部服务连接
- API 密钥、OAuth、证书和回调地址
- 超时、重试和并发参数
- 存储桶、队列和主题名称
- 云权限、数据库权限和第三方白名单

记录配置名称、适用环境、是否必填、来源、设置时机、缺失行为和验证方式。真实密钥不得写入代码、需求文件或发布记录。

## 四、基础设施和外部依赖

判断是否需要：

- 新服务、容器、端口、域名或路由
- DNS、网关、负载均衡、防火墙或安全组
- 存储、消息队列、定时任务或 Worker
- CPU、内存、副本或容量调整
- 运行时升级
- CDN、缓存或搜索索引操作
- 第三方平台配置

依赖代码的基础设施必须由授权人员准备和验证；AI 只负责识别依赖、顺序和完成标准。

## 五、兼容性和发布顺序

检查新旧版本并存时：

- 新前端能否调用旧后端？
- 旧前端和旧客户端能否调用新后端？
- 新生产者和旧消费者能否理解彼此消息？
- 数据库迁移后旧应用能否继续运行？
- 滚动发布期间不同实例能否共享状态？

根据依赖关系写出实际顺序，例如：

```text
兼容性数据库迁移
→ 后端服务
→ 消费者或后台任务
→ 前端或客户端
→ 数据回填
→ 启用功能开关
```

无法兼容时明确维护窗口、停写要求、同步升级范围和用户影响。

## 六、发布前置条件

每项前置条件必须包含人工负责人或执行主体、完成标准和未满足时的处理。以下情况不得向人工发布阶段移交：

- 必填生产配置或权限未准备。
- 数据迁移的耗时、锁表或恢复风险未知。
- 新旧版本无法共存且没有维护窗口。
- 依赖基础设施或第三方配置未就绪。
- 回滚或数据恢复路径不明确。
- 关键生产结果无法验证。

## 七、人工发布后操作清单

根据变更列出需要由授权人员执行的操作：

- 数据库迁移或历史数据回填
- 功能开关启用
- 缓存或 CDN 刷新
- 搜索索引重建
- 定时任务注册
- 消费者和 Worker 启动确认
- 第三方平台配置确认
- 人工生产冒烟验证
- 日志、错误率和核心指标检查
- 数据写入和读取正确性检查

每项必须写完成标准，不得只写“检查一下”。

AI 只定义执行顺序、完成标准和失败处理，不得亲自执行上述生产操作。

## 八、人工生产验证清单

AI 只负责编制清单。授权操作人员应在生产环境确认：

```text
服务健康状态
→ 页面或 API 关键路径
→ 持久化数据结果
→ 刷新或重新读取后的状态
→ 日志、错误率和核心指标
→ 发布后任务完成情况
```

AI 不得连接生产环境或执行这些验证。用户或授权操作人员提供结果后，AI 可以将结果及来源写回需求文件，但不得把转述结果表述成自己的验证结论。

## 九、回滚和故障处理

发布前记录：

```text
回滚触发条件：
应用版本回滚：
配置回滚：
数据库和数据处理：
功能关闭方式：
缓存或索引处理：
回滚后验证：
不可逆操作：
```

不可逆迁移不得虚假标记为可回滚；应说明备份、恢复或前向修复方案。

## 十、写回需求文件

发布准备和人工反馈放在整个需求文件末尾，不重复写入每个单元：

- 是否涉及及当前状态
- 前置条件、人工负责人和发布顺序
- 数据库及配置操作清单
- 发布后必做事项
- 回滚方案
- 人工生产验证结果及来源
- 人工确认的最终发布结论

只有用户或授权操作人员明确确认生产发布、后置操作和生产验证均已完成，AI 才可以把其提供的状态记录为“已发布”；这仍是人工结论，不是 AI 的生产验证。

## AI 阶段完成标准

- 所有发布影响和前置条件已经识别。
- 数据迁移、配置、部署、发布后操作和回滚步骤已经形成供人工审阅的清单。
- 每个生产步骤都有人工负责人、完成标准和失败处理。
- 可在非生产环境验证的脚本或步骤已经验证，未验证项明确标注。
- 需求文件状态为“待人工发布”，且没有写入真实密钥或敏感数据。

## 人工发布完成条件

- 授权操作人员确认发布顺序和必要迁移执行成功。
- 授权操作人员确认发布后必做操作完成。
- 授权操作人员提供生产验证、日志指标和数据正确性结果。
- 未触发回滚，或授权操作人员确认回滚后系统已经恢复。

## 工作流结束

AI 完成发布材料并移交后停止生产相关操作。收到用户或授权操作人员提供的结果时，只负责按来源记录；没有人工确认时，需求必须保持“待人工发布”或“待人工确认”。
