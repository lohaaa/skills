# 发布前准备

## 目标

根据本次实际变更识别代码之外的发布条件，形成可由授权人员审阅的发布前方案、操作顺序和回滚预案。本技能在任何生产操作开始前结束。

## 阶段接口

- **输入**：已经通过 `lohaaa-check` 模块统一验收的需求文件和实际变更。
- **前置门禁**：模块未完成、迁移风险未知或回滚路径不清楚时，不得完成发布准备。
- **输出**：发布前置条件、人工负责人、操作顺序、迁移方案、测试环境脚本检查结果和回滚预案。
- **完成状态**：所有发布前材料完整并完成交接后，将需求文件标记为“发布准备完成”。
- **状态更新**：进入本技能时将需求文件的当前阶段设为“发布前准备”；只记录发布前信息。

## 权限和范围边界

AI **不得**：

- 登录、连接或操作生产环境。
- 执行部署、发布、数据库迁移、历史数据回填或回滚。
- 修改生产配置、密钥、证书、权限、功能开关、网络或基础设施。
- 启停生产任务、Worker、消费者、队列、缓存、索引或第三方集成。
- 读取生产日志、指标、数据库或用户数据。
- 编写或追踪发布后的操作、检查和结果。

AI **可以**：

- 根据代码、配置和测试或预发布环境结果分析发布影响。
- 编制供授权人员审阅的命令、迁移步骤、发布顺序和回滚预案，但不得在生产执行。
- 在用户明确授权的测试或预发布环境检查发布脚本和步骤。
- 明确每个发布步骤的人工负责人、前置条件、预期结果和失败处理。

任何生产和发布后工作均不属于本技能范围。发布前材料移交后，本技能必须结束。

## 一、建立变更清单

逐项判断是否涉及：

```text
应用代码
数据库结构
历史数据
配置和环境变量
密钥、证书和权限
依赖及运行时版本
基础设施和网络
定时任务和后台 Worker
消息队列、主题和消费者
缓存、搜索索引和静态资源
第三方服务和回调
API 及客户端兼容性
日志、指标和告警
```

不涉及的项目明确标记为“不适用”，不要生成无意义步骤。

## 二、数据库结构和数据迁移

检查表、字段、类型、默认值、非空、唯一、外键、索引、视图、函数、触发器、扩展和权限变化。

每项迁移必须明确：

```text
执行时机：
执行者：
预计耗时：
数据量和锁表风险：
对旧版本代码的影响：
失败处理：
是否可逆：
预期结果与人工确认方式：
```

历史数据迁移还要确认分批、幂等、暂停恢复、进度监控和完整性验证。

需要滚动或不停机发布时优先采用：

```text
添加兼容的新结构
→ 准备兼容新旧结构的代码
→ 规划历史数据分批迁移
→ 定义读写切换条件
→ 定义旧结构后续清理条件
```

不得在同一次发布中删除旧结构并使应用回滚失效，除非明确采用停机方案并接受风险。

## 三、配置、密钥和权限

确认新增或修改的：

- 环境变量和配置文件
- 功能开关
- 数据库或外部服务连接
- API 密钥、OAuth、证书和回调地址
- 超时、重试和并发参数
- 存储桶、队列和主题名称
- 云权限、数据库权限和第三方白名单

记录配置名称、适用环境、是否必填、来源、设置时机、缺失行为和验证方式。真实密钥不得写入代码、需求文件或发布记录。

## 四、基础设施和外部依赖

判断是否需要：

- 新服务、容器、端口、域名或路由
- DNS、网关、负载均衡、防火墙或安全组
- 存储、消息队列、定时任务或 Worker
- CPU、内存、副本或容量调整
- 运行时升级
- CDN、缓存或搜索索引操作
- 第三方平台配置

依赖代码的基础设施必须由授权人员准备和验证；AI 只负责识别依赖、顺序和完成标准。

## 五、兼容性和发布顺序

检查新旧版本并存时：

- 新前端能否调用旧后端？
- 旧前端和旧客户端能否调用新后端？
- 新生产者和旧消费者能否理解彼此消息？
- 数据库迁移后旧应用能否继续运行？
- 滚动发布期间不同实例能否共享状态？

根据依赖关系写出实际顺序，例如：

```text
兼容性数据库迁移
→ 后端服务
→ 消费者或后台任务
→ 前端或客户端
→ 数据回填
→ 启用功能开关
```

无法兼容时明确维护窗口、停写要求、同步升级范围和用户影响。

## 六、发布前置条件

每项前置条件必须包含人工负责人或执行主体、完成标准和未满足时的处理。以下情况不得向人工发布阶段移交：

- 必填生产配置或权限未准备。
- 数据迁移的耗时、锁表或恢复风险未知。
- 新旧版本无法共存且没有维护窗口。
- 依赖基础设施或第三方配置未就绪。
- 回滚或数据恢复路径不明确。
- 关键发布步骤缺少完成标准或人工负责人。

## 七、发布前交接清单

交接材料必须包含：

- 发布版本或构建产物标识
- 数据库结构和历史数据迁移方案
- 配置、密钥、权限和基础设施前置条件
- 服务、任务、消费者和客户端的发布顺序
- 维护窗口、停写要求和用户影响
- 每个步骤的人工负责人、预期结果和失败处理
- 回滚触发条件、操作顺序和不可逆事项
- 已在测试或预发布环境检查的内容及尚未检查的风险

交接清单只描述发布前已经准备好的内容，不包含生产操作、发布后任务或生产结果记录。

## 八、写回需求文件

只写入发布前信息：

- 变更影响和是否涉及
- 发布前置条件
- 数据库、数据、配置和基础设施准备
- 兼容性与发布顺序
- 人工负责人和维护窗口
- 回滚预案与不可逆风险
- 测试或预发布环境检查结果
- 未满足条件和阻塞项

不得在需求文件中新增生产执行、发布后操作或生产结果栏目。

## 阶段完成标准

- 所有发布影响和前置条件已经识别。
- 数据迁移、配置、基础设施、发布顺序和回滚预案已经形成清单。
- 每个步骤都有人工负责人、预期结果和失败处理。
- 可在测试或预发布环境检查的脚本或步骤已经检查，未检查风险明确标注。
- 没有真实密钥、敏感数据或生产访问行为。
- 需求文件状态为“发布准备完成”。

完成交接后结束工作流；不得继续参与生产或发布后的任何步骤。
