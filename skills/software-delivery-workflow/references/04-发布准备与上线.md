# 发布准备与上线

## 目标

根据本次实际变更识别代码之外的发布条件，明确执行顺序、发布后动作、生产验证和回滚方案。发布完成必须以生产结果为准，而不是以构建或部署命令结束为准。

## 一、建立变更清单

逐项判断是否涉及：

```text
应用代码
数据库结构
历史数据
配置和环境变量
密钥、证书和权限
依赖及运行时版本
基础设施和网络
定时任务和后台 Worker
消息队列、主题和消费者
缓存、搜索索引和静态资源
第三方服务和回调
API 及客户端兼容性
日志、指标和告警
```

不涉及的项目明确标记为“不适用”，不要生成无意义步骤。

## 二、数据库结构和数据迁移

检查表、字段、类型、默认值、非空、唯一、外键、索引、视图、函数、触发器、扩展和权限变化。

每项迁移必须明确：

```text
执行时机：
执行者：
预计耗时：
数据量和锁表风险：
对旧版本代码的影响：
失败处理：
是否可逆：
完成验证：
```

历史数据迁移还要确认分批、幂等、暂停恢复、进度监控和完整性验证。

需要滚动或不停机发布时优先采用：

```text
添加兼容的新结构
→ 发布兼容新旧结构的代码
→ 分批迁移历史数据
→ 切换读写
→ 验证稳定
→ 后续发布删除旧结构
```

不得在同一次发布中删除旧结构并使应用回滚失效，除非明确采用停机方案并接受风险。

## 三、配置、密钥和权限

确认新增或修改的：

- 环境变量和配置文件
- 功能开关
- 数据库或外部服务连接
- API 密钥、OAuth、证书和回调地址
- 超时、重试和并发参数
- 存储桶、队列和主题名称
- 云权限、数据库权限和第三方白名单

记录配置名称、适用环境、是否必填、来源、设置时机、缺失行为和验证方式。真实密钥不得写入代码、需求文件或发布记录。

## 四、基础设施和外部依赖

判断是否需要：

- 新服务、容器、端口、域名或路由
- DNS、网关、负载均衡、防火墙或安全组
- 存储、消息队列、定时任务或 Worker
- CPU、内存、副本或容量调整
- 运行时升级
- CDN、缓存或搜索索引操作
- 第三方平台配置

依赖代码的基础设施必须先准备并验证。

## 五、兼容性和发布顺序

检查新旧版本并存时：

- 新前端能否调用旧后端？
- 旧前端和旧客户端能否调用新后端？
- 新生产者和旧消费者能否理解彼此消息？
- 数据库迁移后旧应用能否继续运行？
- 滚动发布期间不同实例能否共享状态？

根据依赖关系写出实际顺序，例如：

```text
兼容性数据库迁移
→ 后端服务
→ 消费者或后台任务
→ 前端或客户端
→ 数据回填
→ 启用功能开关
```

无法兼容时明确维护窗口、停写要求、同步升级范围和用户影响。

## 六、发布前置条件

每项前置条件必须包含负责人或执行主体、完成标准和未满足时的处理。以下情况停止发布：

- 必填生产配置或权限未准备。
- 数据迁移的耗时、锁表或恢复风险未知。
- 新旧版本无法共存且没有维护窗口。
- 依赖基础设施或第三方配置未就绪。
- 回滚或数据恢复路径不明确。
- 关键生产结果无法验证。

## 七、发布后必做操作

根据变更列出并执行：

- 数据库迁移或历史数据回填
- 功能开关启用
- 缓存或 CDN 刷新
- 搜索索引重建
- 定时任务注册
- 消费者和 Worker 启动确认
- 第三方平台配置确认
- 生产冒烟验证
- 日志、错误率和核心指标检查
- 数据写入和读取正确性检查

每项必须写完成标准，不得只写“检查一下”。

## 八、生产验证

在真实生产表面验证最小关键路径：

```text
确认服务健康
→ 执行页面或 API 冒烟
→ 检查持久化数据
→ 刷新或重新读取确认结果
→ 检查日志、错误率和核心指标
→ 确认发布后任务完成
```

验证应使用安全的生产测试方式，不制造不可清理的真实业务数据或绕过权限。

## 九、回滚和故障处理

发布前记录：

```text
回滚触发条件：
应用版本回滚：
配置回滚：
数据库和数据处理：
功能关闭方式：
缓存或索引处理：
回滚后验证：
不可逆操作：
```

不可逆迁移不得虚假标记为可回滚；应说明备份、恢复或前向修复方案。

## 十、写回需求文件

发布准备和结果放在整个需求文件末尾，不重复写入每个单元：

- 是否涉及及当前状态
- 前置条件和发布顺序
- 数据库及配置操作
- 发布后必做事项
- 回滚方案
- 生产验证结果
- 最终发布结论

只有生产发布、后置操作和生产验证均完成，需求才能标记为“已发布”。

## 发布完成标准

- 所有发布前置条件已满足。
- 发布顺序和必要迁移执行成功。
- 发布后必做操作完成。
- 页面或 API 生产冒烟通过。
- 日志、指标和数据正确性无异常。
- 未触发回滚，或回滚后系统已恢复并验证。
- 需求文件已记录真实发布结果。
